01

Authentication

EpicHub uses JWT Bearer authentication. All protected endpoints require an Authorization: Bearer <accessToken> header. Access tokens expire after 15 minutes. Use the refresh endpoint to obtain a new token.

1

Register or Login

POST /auth/register or /auth/login. Receive accessToken + refreshToken (set as httpOnly cookie).

2

Include Bearer Token

Add Authorization: Bearer {accessToken} to every protected request header.

3

Token Expires (15 min)

API returns 401 Unauthorized with {"error":"token_expired"}.

4

Refresh Token

POST /auth/refresh. The httpOnly cookie is sent automatically. Receive new accessToken. No credentials needed.

Bookings API

POST /api/v1/orders/checkout Checkout all Draft EventItems in an Event Customer
Atomic Transaction

This endpoint performs: Order + OrderItems creation → EventItem status → Draft to Ordered → Event status → Draft to Confirmed → PaymentIntent creation — all in a single DB transaction. If any step fails, the entire operation rolls back.

05

Webhooks

EpicHub receives webhooks from Paymob (payment events). All incoming webhooks are verified via HMAC-SHA256. EpicHub also emits outbound webhooks to enterprise integrations (Phase 2).

HMAC Verification — Required

All Paymob webhooks include an x-hmac-signature header. Verify it: HMAC-SHA256(request_body, PAYMOB_WEBHOOK_SECRET). Reject any request where signatures do not match. This prevents spoofed payment confirmations.

Inbound — Paymob Payment Webhooks

payment.success

Payment Captured Successfully

Updates Order.PaymentStatus → Paid. Triggers booking confirmation notifications to customer (email + SMS) and vendor (SignalR). Escrow hold begins.

payment.failed

Payment Failed

Updates Order.PaymentStatus → Failed. Event and EventItems revert to Draft status. Customer notified to retry.

refund.processed

Refund Completed

Updates Order.PaymentStatus → Refunded. Linked to a dispute resolution or cancellation action. Customer notified by email.

payout.completed

Vendor Payout Transferred

Updates payout record status → Completed. Vendor notified by email with gross/net breakdown. Audit log entry created.

Webhook Endpoint

POST /api/v1/payments/webhook Receives Paymob payment events HMAC only
Headers Required
x-hmac-signature: {HMAC-SHA256 of body}
Content-Type: application/json
Idempotency

Each webhook payload includes a unique transactionId. The endpoint checks for existing records with this ID before processing — duplicate deliveries are silently ignored with a 200 response.

Error Reference

All error responses use a consistent JSON envelope. Never parse HTTP status codes alone — always read the errorCode field for precise error type.

Error Response Envelope
{
  "status": 400,
  "errorCode": "VALIDATION_FAILED",   // machine-readable code
  "message": "EventDate must be in the future",
  "details": [                          // optional field-level errors
    { "field": "eventDate", "error": "Must be future date" }
  ],
  "traceId": "00-abc123-def456-00"        // for support escalation

SDK & Integration Notes

Angular HTTP Client Setup

auth.interceptor.ts
// Add to app.module.ts providers
@Injectable()
export class AuthInterceptor implements HttpInterceptor {
  intercept(req: HttpRequest<any>, next: HttpHandler) {
    const token = this.authService.getToken();
    if (token) {
      req = req.clone({
        setHeaders: { Authorization: `Bearer ${token}` }
      });
    }
    return next.handle(req).pipe(
      catchError(err => {
        if (err.status === 401 && err.error.errorCode === 'TOKEN_EXPIRED') {
          return this.authService.refresh().pipe(
            switchMap(() => next.handle(this.addToken(req)))
          );
        }
        return throwError(() => err);
      })
    );
  }
}

SignalR Connection

signalr.service.ts
const connection = new HubConnectionBuilder()
  .withUrl('/hubs/notifications', {
    accessTokenFactory: () => this.authService.getToken()
  })
  .withAutomaticReconnect()
  .build();

// Listen for booking notifications
connection.on('BookingConfirmed', (data) => {
  this.store.dispatch(bookingConfirmed({ payload: data }));
});

connection.on('NewBookingRequest', (data) => {
  // Vendor receives this on new booking
  this.store.dispatch(newBookingReceived({ payload: data }));
});

await connection.start();
