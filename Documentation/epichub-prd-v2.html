01

Product Vision

EpicHub is a web-based two-sided marketplace that allows customers to discover, compare, and book event service vendors — and allows vendors to list, manage, and fulfil bookings — all within a single platform. No phone calls. No bank transfers. No chasing confirmations.

Product Purpose

EpicHub replaces the fragmented, WhatsApp-driven vendor search process in Egypt with a structured digital marketplace. The core product promise: a customer can go from "I need a photographer for my wedding" to "booking confirmed, payment secured" without ever leaving the platform.

The Product Does Three Things

🔍

Vendor Discovery

Customers search, filter, and compare verified vendor profiles across all event service categories using real-time data — price, availability, ratings, location.

📅

Event Planning & Booking

Customers build an event plan, shortlist services, and complete a secure end-to-end booking with payment in a single uninterrupted flow on the platform.

⚙️

Vendor & Order Management

Vendors manage their availability, profiles, and incoming bookings. The platform manages payments, escrow, notifications, and post-event reviews.

Product Scope

Phase 1 defines the initial product boundary. Every feature outside this scope is explicitly deferred — not rejected.

✓  In Scope — Phase 1
  • Customer-facing web platform for vendor search, filtering, and booking
  • Event planning layer — create an Event, add EventItems, proceed to Order
  • Real-time vendor availability calendar visible to customers
  • Secure end-to-end booking flow with escrow payment
  • Vendor onboarding portal — submit profile, services, pricing, calendar
  • Vendor dashboard — manage bookings, availability, performance
  • EpicHub internal CMS — editorial control over all vendor content
  • AI chatbot with human escalation routing
  • Loyalty points system for repeat customers
  • Post-event automated review and feedback survey
  • Responsive web — desktop, tablet, mobile (PWA-ready)
  • English language interface (Phase 1)
✗  Out of Scope — Phase 1
  • Native iOS and Android mobile applications
  • Arabic RTL interface (Phase 2 — internationalization)
  • BNPL / installment payment integrations (Tamara, tabby)
  • Direct event execution by EpicHub as event producer
  • Student and campus organizer segment
  • International markets beyond Egypt
  • Professional planner agency portal with passive income model
  • Corporate enterprise module with RFQ management
  • Real-time vendor-customer in-app messaging
  • Vendor contract generation and e-signature
03

User Personas

Four distinct user types interact with the EpicHub platform. Each has a different interface, set of permissions, and product journey. Product decisions must be evaluated against all four.

🎉

The Customer

Primary · Demand Side
End User
  • Plans a personal or small corporate event (wedding, birthday, conference)
  • Searches, shortlists, and books vendors through the customer portal
  • Manages their events, booking history, and loyalty points via dashboard
  • Submits post-event reviews for completed bookings
  • Raises disputes and uses chatbot support when needed
📸

The Vendor

Primary · Supply Side
Service Provider
  • Submits business profile, services, pricing, and portfolio for EpicHub review
  • Manages their availability calendar to reflect real bookings
  • Receives booking notifications and accepts or declines via vendor dashboard
  • Views performance analytics and payout history
  • Chooses a subscription tier (Basic / Standard / Premium)
🛡️

EpicHub Ops

Internal · Platform Admin
Admin
  • Reviews and publishes vendor profiles via internal CMS
  • Manages promotional campaigns, loyalty offers, and featured placements
  • Handles dispute resolution with access to full evidence and audit trail
  • Monitors platform-wide analytics dashboard (GMV, bookings, ratings)
  • Manages chatbot escalation queue and human agent assignments
📋

Professional Planner

Secondary · Phase 2
Phase 2
  • Uses EpicHub to source vendors for client events professionally
  • Requires bulk access, single-invoice management, and agency discount
  • Portal and passive income model deferred to Phase 2
  • In Phase 1: uses standard customer portal only

Feature Specifications

All platform features organized by functional area. Priority uses MoSCoW. Each feature is a product capability — not a business requirement.

Discovery & Search

FeatureDescriptionPriority
Vendor Search Full-text and faceted search by category, event type, location, and date. Results ranked by matchmaking score (rating × availability × relevance). MUST
Budget Filter Slider-based budget filter that limits search results to vendors whose packages fall within the customer's specified range. Applied in real time without page reload. MUST
Vendor Profile Page Dedicated page per vendor showing: verified badge, category, service list with pricing, portfolio gallery, average rating, review history, and real-time availability calendar preview. MUST
Shortlist & Compare Save up to 5 vendors per category to a persistent shortlist. Side-by-side comparison view across price, rating, availability, and inclusions. SHOULD
Matchmaking Algorithm Backend scoring engine surfaces most relevant vendors based on event type, date, location, and budget inputs. Weights: availability (40%), rating (35%), category match (25%). MUST

Event Planning & Booking

FeatureDescriptionPriority
Event Planner Customer creates a named Event (title, type, date, location, budget). Multiple active events supported per user. Events persist independently from orders. MUST
EventItem Management Add Products or Packages to an Event plan. Price and vendor name are snapshotted at add-time. Items show Draft → Ordered status transitions. MUST
Real-Time Availability Full availability calendar per vendor. Blocked dates propagate to search results within 60 seconds of vendor update. Prevents double-booking at the database layer. MUST
Checkout & Payment Single payment flow covering all selected EventItems. Total cost (service + platform fee) shown before confirmation. Funds held in escrow per vendor until delivery. MUST
Booking Confirmation Instant confirmation notification to customer and vendor (email + in-platform) within 60 seconds of payment success. Generates Order and OrderItems records. MUST
Delivery Confirmation & Payout Customer confirms service delivery post-event. Triggers escrow release to vendor within 72 hours. If no action within 48h of event date, auto-releases escrow. MUST

Vendor Portal

FeatureDescriptionPriority
Vendor Onboarding Portal Multi-step submission form: business details, service categories, pricing, portfolio upload, license document. Submits to EpicHub ops review queue. Not live until approved. MUST
Availability Calendar Interactive calendar editor for vendors to mark dates available, booked, or blocked. Changes sync to customer-facing search within 60 seconds. MUST
Booking Management Incoming booking queue with accept / decline / modify actions. Decline requires a reason. Status tracking from pending → confirmed → delivered. MUST
Performance Dashboard Analytics for Standard/Premium tier vendors: booking conversion, profile views, revenue trends, average rating over selectable time periods. SHOULD
Subscription Management Vendor selects and upgrades between Basic / Standard / Premium tiers. Tier benefits clearly displayed. Billing managed via payment gateway subscription. MUST

CRM, Support & Admin

FeatureDescriptionPriority
Internal CMS EpicHub ops portal for reviewing, editing, approving, rejecting, and publishing vendor profiles. Full editorial control. No vendor content goes live without approval. MUST
AI Chatbot Embedded support bot trained on EpicHub FAQ, booking flows, and policy. Handles ≥80% of queries without human escalation. Escalates via confidence threshold to human agent queue. MUST
Loyalty Points System Points earned per confirmed delivery (not booking). Displayed in customer dashboard. Redeemable against future booking fees. Expire after 12 months. SHOULD
Post-Event Review System Auto-triggered survey 24h post-event. Review only enabled after confirmed delivery. One review per booking. Feeds into vendor aggregate rating and platform analytics. SHOULD
Promotions Engine Ops-managed promo panel: create discount codes, featured placements, seasonal campaigns. No developer intervention required. Schedule start/end dates. SHOULD

User Flows

The two critical customer journeys that define the product experience. Every UI decision should be evaluated against these flows.

Primary Flow — Customer Books a Vendor

01

Create Event

Customer creates a named Event with type, date, location, and optional budget

02

Search & Filter

Searches vendors by category with matchmaking score ranking results

03

Review Profile

Views vendor profile: portfolio, pricing, ratings, availability calendar

04

Add to Event

Adds Product or Package to EventItem. Price and name are snapshotted

05

Checkout

Reviews total cost, confirms, pays. Funds go to escrow per vendor

06

Vendor Confirms

Vendor accepts booking within 24h. Calendar blocked. Customer notified

07

Event Day

Service delivered. Customer confirms delivery. Escrow released to vendor in 72h

08

Review

Auto survey 24h post-event. Customer rates and reviews. Points credited

Secondary Flow — Vendor Gets Onboarded

01

Apply

Vendor submits business details, portfolio, pricing, and license via portal

02

Ops Review

EpicHub ops reviews quality, authenticity, and completeness via CMS

03

Approved

Profile published with Verified badge. Vendor appears in search results

04

Choose Tier

Vendor selects subscription tier and completes payment setup

05

Manage Calendar

Vendor marks availability. Real-time sync to customer-facing results

06

Receive Bookings

Booking alerts arrive. Vendor accepts, declines, or requests modification

Architecture Decision

The data model follows a two-layer separation: Event / EventItem (planning layer — persists forever) and Order / OrderItem (financial layer — created at checkout). The Order has a nullable EventId FK linking back to the plan. This means the Event record survives independently of any Order state or cancellation.

Non-Functional Requirements

These are product-level quality requirements — not business goals. They define how the product must behave technically for it to be considered production-ready.

⚡

Performance

All customer-facing pages must be interactive and usable on mobile connections.

TTI ≤ 3s on 4G
Lighthouse ≥ 80
🟢

Availability

Platform uptime target on a rolling 30-day basis. Maintenance windows restricted to 02:00–05:00 EGT.

99.5% uptime
🔒

Security

Data encrypted at rest and in transit. Pre-launch penetration testing required. Zero critical vulnerabilities at release.

AES-256 at rest
TLS 1.3 in transit
📱

Responsiveness

Fully functional across all viewport sizes. No horizontal scroll or broken layouts at any breakpoint.

≥ 320px mobile
≥ 1280px desktop
♿

Accessibility

Platform must meet web accessibility standards for all users, including keyboard navigation and screen reader support.

WCAG 2.1 AA
📈

Scalability

Architecture must support horizontal scaling to handle surge load without redesign. Geographic expansion must require zero core re-engineering.

10× baseline load
🔄

Real-time Sync

Vendor calendar changes must propagate to customer-facing search without a page refresh.

≤ 60s sync
🌍

Internationalisation

i18n must be built in from day one — supporting Arabic RTL in Phase 2 with no structural code change required.

Angular i18n
CSS logical props
📦

API Standards

All endpoints must follow RESTful conventions, versioned, and fully documented before any frontend integration begins.

OpenAPI 3.0
Versioned /v1/
